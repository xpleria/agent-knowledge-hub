# Technologies index

- **Scope:** Which technology-specific knowledge exists, and how is it grouped by technology, facet and page?
- **Keywords:** technologies, technology, facet, Godot, dotnet, game engine, traps, index, grouping, tool-specific, labelled
- **Status:** current
- **Updated:** 2026-11-07
- **Sources:** the hub owner's technology-hierarchy decision (2026-11-07); the technology pages' own sources

Technology pages hold knowledge that applies to one tool or platform. They are grouped as technology, then facet, then page. Each page is labelled with its technology, its facet and the version it was observed on. They are not project-invariant rules: check the version you use before applying a trap.

Only broadly useful, reusable knowledge belongs here. A project's own code pattern belongs in that project. Technology-independent habits belong in [practices/](../practices/00-practices-index.md), and scenarios belong in [recall/](../recall/00-recall-index.md).

## Reading guide

- Working with Godot: read [godot/00-godot-index.md](godot/00-godot-index.md), then the page for the facet you work in.
- Any other technology: no page yet. Do not apply one technology's traps to another.
- Deciding where new technology content goes: read [grouping-rules.md](grouping-rules.md) first.
